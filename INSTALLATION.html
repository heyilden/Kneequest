Knee Quest / Version 4.0 / 19 octobre 2026

Ton journal, partout.

Google pour te connecter. Firebase pour sauvegarder. GitHub Pages pour ouvrir Knee Quest sur iPhone et ordinateur.

Le chemin le plus simple

GitHub Pages sert l'application. Firebase connecte ton compte Google et conserve ton journal. Tu n'as besoin ni de Firebase Hosting, ni de serveur personnel, ni de ligne de commande pour cette installation.

Avant tout : exporte la sauvegarde JSON de ta V3. Garde-la hors du dossier GitHub. L'historique qui se trouve sur ton ancien appareil ne peut pas etre recupere automatiquement par une nouvelle adresse web.

Il n'y a aucun compte configure dans les fichiers fournis. La premiere mise en service necessite les etapes ci-dessous. Les donnees cloud ne sont confirmees qu'apres l'affichage Synchronise avec Google.

1. Preparer le projet Firebase

  1. Ouvre la console Firebase avec ton compte Google. Cree un projet Knee Quest, ou reutilise celui que tu as deja cree.
  2. Garde l'offre Spark. Google Analytics n'est pas necessaire. Cette version n'utilise ni Cloud Functions ni Cloud Storage.
  3. Dans les parametres du projet, section Tes applications, ajoute une application Web </>. Nom : Knee Quest. Ne coche pas Firebase Hosting.
  4. Garde la configuration firebaseConfig affichee : tu la colleras a l'etape 4.

L'offre gratuite actuelle comprend notamment 1 Gio Firestore Standard, 50 000 lectures et 20 000 ecritures par jour. Ce n'est pas un service illimite : consulte l'utilisation dans Firebase. Tarifs officiels Firebase.

2. Autoriser la connexion Google

Dans Build / Authentication, demarre le service, puis ouvre Sign-in method / Fournisseurs de connexion. Active Google, choisis l'adresse d'assistance demandee et enregistre.

Ne configure pas Gmail, Drive, un secret OAuth ou un compte de service : cette application demande seulement la connexion Google.

Configuration Google Authentication.

3. Creer et proteger la base de donnees

  1. Dans Build / Firestore Database, cree une base Standard, identifiant (default), en mode production. Choisis une localisation adaptee ; pour ton usage au Luxembourg, une localisation europeenne peut etre pertinente.
  2. Ouvre l'onglet Rules / Regles de Firestore. Remplace tout son contenu par les regles ci-dessous, puis clique sur Publish / Publier.

Afficher les regles completes
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function owner(uid) {
      return request.auth != null && request.auth.uid == uid
        && request.auth.token.email_verified == true
        && request.auth.token.firebase.sign_in_provider == 'google.com';
    }
    function validRecord() {
      return request.resource.data.keys().hasOnly(['payload', 'deleted', 'rev', 'updatedAt'])
        && request.resource.data.payload is string
        && request.resource.data.payload.size() <= 800000
        && request.resource.data.deleted is bool
        && request.resource.data.rev is int
        && request.resource.data.updatedAt == request.time
        && (!request.resource.data.deleted || request.resource.data.payload == '');
    }
    match /users/{uid}/records/{recordId} {
      allow read: if owner(uid);
      allow create: if owner(uid) && validRecord() && request.resource.data.rev == 1;
      allow update: if owner(uid) && validRecord()
        && request.resource.data.rev == resource.data.rev + 1;
      // Keep revision tombstones so an offline device cannot resurrect a deletion.
      allow delete: if false;
    }
    match /{document=**} { allow read, write: if false; }
  }
}

N'utilise pas le mode test ouvert. Les regles fournies limitent les lectures et ecritures au compte Google proprietaire de chaque journal. Les regles Firebase sont indispensables : masquer un bouton dans l'application ne protegerait pas tes donnees.

Le code du site sera public. Tes notes de douleur, seances et questionnaires sont stockes dans Firestore, pas dans le depot GitHub. Le proprietaire du projet Firebase dispose toutefois d'un acces administrateur ; ce n'est pas un chiffrement de bout en bout.

4. Creer ton fichier de configuration

Colle ici le bloc const firebaseConfig = { ... } fourni par Firebase. Le formulaire extrait uniquement quatre valeurs publiques. Il n'execute pas le texte colle et ne l'envoie a aucun serveur.

Ou remplir le fichier manuellement

Dans firebase-config.js, remplace seulement les quatre chaines vides par les valeurs exactes de Firebase. Conserve window.KQ_FIREBASE_CONFIG.

window.KQ_FIREBASE_CONFIG = {
  apiKey: "VALEUR_FIREBASE",
  authDomain: "TON-PROJET.firebaseapp.com",
  projectId: "TON-PROJET",
  appId: "VALEUR_FIREBASE"
};

Garde l'authDomain fourni par Firebase. Ne le remplace pas par ton adresse github.io. La connexion utilise une fenetre Google, pas une redirection vers un faux point d'authentification sur GitHub.

Ces valeurs de configuration Web, dont l'API key Firebase, ne sont pas des mots de passe administrateur. Ne publie jamais une cle privee, un secret OAuth ou un fichier de compte de service. Explications sur les cles Firebase.

5. Publier tous les fichiers sur GitHub Pages

  1. Decompresse KneeQuest-v4-GitHub.zip. Remplace le fichier firebase-config.js par celui cree a l'etape 4.
  2. Dans GitHub, cree ou ouvre ton depot kneequest. Pour GitHub Free, choisis un depot public. Ajoute les fichiers decomprimes a la racine : index.html doit etre visible directement, pas au fond d'un sous-dossier.
  3. Utilise Add file > Upload files, puis Commit changes. N'envoie pas seulement le ZIP. Tous les fichiers JavaScript, CSS et les icones doivent rester ensemble. Le fichier cache .nojekyll est fourni ; tu peux aussi le creer vide via Add file.
  4. Ouvre Settings > Pages. Source : Deploy from a branch. Branche : main. Dossier : /(root). Enregistre.
  5. Attends la publication. Recopie l'adresse HTTPS affichee par GitHub, par exemple https://ton-compte.github.io/kneequest/. Ce n'est pas l'adresse de la page du depot github.com/....

N'ajoute jamais ton export JSON, une capture de tes ressentis ou d'autres donnees personnelles au depot. Les exercices preconfigures du code sont publics ; les donnees de ton journal ne doivent pas l'etre.

Documentation GitHub Pages.

6. Ajouter le domaine autorise

Dans Firebase : Authentication > Settings / Parametres > Authorized domains / Domaines autorises > Add domain.

Ajoute seulement ton-compte.github.io, sans https:// et sans /kneequest/. Tu peux extraire le bon texte ici :

Conserve les domaines Firebase deja presents. Un domaine personnalise doit aussi etre ajoute s'il est utilise pour ouvrir l'application.

7. Importer ton historique et verifier la synchronisation

  1. Ouvre le site HTTPS publie. Avant la premiere connexion, utilise Reglages > Restaurer un fichier pour importer le JSON de ton ancienne version. Verifie les dates de ton historique.
  2. Appuie sur Se connecter avec Google et choisis ton compte. Si son journal cloud est vide, accepte explicitement d'y envoyer le journal de cet appareil.
  3. Attends Synchronise avec Google. Une mention En attente ou Erreur ne constitue pas une sauvegarde cloud.
  4. Ouvre la meme adresse sur ton iPhone dans Safari et connecte-toi au meme compte. Verifie qu'une ancienne seance et sa date apparaissent, puis qu'une petite modification de note se retrouve sur l'autre appareil.
  5. Apres cette verification, utilise le menu Partager de Safari pour ajouter le site a l'ecran d'accueil. L'ouverture de la piece jointe HTML ou de l'apercu du fichier GitHub n'est pas le chemin d'utilisation.

Si le cloud contient deja un journal, il est charge sans importer silencieusement le journal invite. Ne restaure un ancien JSON par-dessus un compte connecte que pour remplacer volontairement son journal, apres avoir exporte les deux versions.

Une seule fenetre d'edition par navigateur est autorisee lorsque le navigateur fournit Web Locks. Sur un navigateur sans ce mecanisme, evite plusieurs onglets simultanes. Deux appareils distincts peuvent se synchroniser ; les modifications concurrentes d'un meme element demandent un choix explicite.

La connexion par fenetre est l'une des solutions officielles Firebase aux restrictions de stockage tiers, notamment Safari. Une fenetre peut encore etre bloquee : le message de l'application propose alors de reessayer depuis Safari. Connexion Google et stockage tiers.

Ce que sauvegarde signifie ici

Les changements sont conserves localement et envoyes automatiquement au compte connecte. La confirmation verte suit l'accuse de reception du serveur. Hors connexion, ils restent en attente et sont renvoyes au retour du reseau ; un redemarrage totalement hors ligne de l'authentification n'est pas garanti. Une copie locale pleine ou bloquee declenche une alerte.

Aucun logiciel ne peut promettre de ne jamais perdre des donnees. Garde un export periodique independant, protege ton compte Google et attends la confirmation cloud avant d'effacer le navigateur ou de changer d'appareil. Une suppression volontaire dans l'historique est aussi synchronisee : synchronisation et sauvegarde anti-erreur sont deux choses differentes.

La configuration Google reelle, les regles dans ton projet, GitHub Pages et Safari sur ton iPhone n'ont pas ete testes avec tes identifiants. Le rapport distingue les tests executes et ces limites.
